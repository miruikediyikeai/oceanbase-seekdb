# 全文索引第五轮优化

本轮以 `64508f5e3f5b58c6be07c4e284a6cf721942a683` 为对照。其正式反馈为 26.2619/50，综合提升率 26.2619%，四项查询耗时为 0.8183 / 1.2105 / 0.9571 / 1.6272 ms；三项构建为 5.754 / 4.427 / 2.122 s。原始反馈见 [正式报告](../benchmarks/fts-2026-round5/submitted-round4-feedback.json)。正式 baseline 尚未提供，本轮本地 A/B 只表示增量，不预测正式分数。

## 定位和修改

沿用原始 20,000 行数据，对 IK 分词及 LIMIT 查询重新进行用户态 CPU 采样。IK 路径涉及字典编码、临时分配及仲裁输出。源码检查发现，仲裁结果已经按字节位置输出，却每篇文档创建哈希表、逐次插入链，并在输出字符时再次查哈希表。将链保存为带 16 个内联槽的有序数组，输出时随递增字节位置移动数组游标，可减少临时分配和哈希操作。

插入通常直接追加，仍支持乱序插入及重复位置报错；数组增长时保留分配失败传播。链冲突判定、smart/max_word 的最优链选择、词频、字符解码及补充单字逻辑均沿用原实现。数组属于一次仲裁调用，跨线程不共享。

LIMIT 查询的 EXPLAIN 显示相关性倒序及内部 Top-K，实际采样出现 BMW 的 pivot 评估、block-max 读取和 posting `advance_to`。它必须选择相关性最高的结果，不能在前 20 条命中后停止。批内跳转原先逐条比较 ID；本轮保留近距离顺序比较，连续跳过 8 条后，仅对没有 skip 位的有序批次使用指数探测和二分下界查找。该阈值用于摊薄搜索初始化成本，不改变输入或评分。稀疏批次和跨批存储跳转保留原路径。

文档 ID 类型及字符集为 `VARCHAR/BINARY` 时，复用已有的二进制 ID 比较器，保留 NULL、字节序和长度比较；其他类型继续使用原比较函数。相关性公式、候选筛选、BMW 上界、Top-K 堆以及并列分数的处理顺序均未修改。

## 回归验证

新增 `fts_ik_bmw_seek_regression`，预期由上一轮正式提交的二进制生成。覆盖 2,053 行包含空文本的文档、删除及更新、稀疏词、批次边界、LIMIT/OFFSET、BOOLEAN 模式、预编译重用，及超过 16 条链的 IK 输入和两种分词模式。

另增加 1,302 组完整结果摘要差分，包含 852 组随机/长文本分词、420 组排名分页及 30 组显式排序查询；旧版本先重复核对结果稳定，再与候选在同一份索引上比较。既有 1,668 组完整结果、1,062 组 Unicode 分词差分及 8 连接并发解析继续执行。跨版本比较始终使用同一份索引，避免重建统计变化混入分数对比。命中数仅作辅助，另核对实际 ID、分数和分页结果。
