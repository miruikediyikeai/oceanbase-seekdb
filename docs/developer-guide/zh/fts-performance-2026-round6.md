# 全文索引第六轮优化

以 `3460b431dfcf601d14588bb9eca296702abc4184` 为对照。用户最新正式反馈为 25.4804/50，上一轮为 26.2619/50；[原始反馈](../benchmarks/fts-2026-round6/submitted-round5-feedback.json) 完整保留。正式 baseline 未提供，以下只说明本地增量，不换算正式分数。

## 瓶颈与修改

1. **解析配置复用。** 源码中的 TOKENIZE 初始化、全文 DML 的 `check_is_the_same` 都会重新解析相同 JSON 配置，创建临时 JSON 对象。`ObFTParserProperty::parse_for_parser_helper` 现在使用有界线程局部缓存，以完整配置字节和解析器名称、版本为键，只保存已成功解析的数值设置。每线程新增约 2.2 KB；超长配置走原路径，失败结果不缓存。命中时只更新当前解析器原本会设置的字段，保留 helper 重用时其他字段的行为。实际字典加载仍执行，不缓存文本、分词或检索结果。

2. **减少独立 arena。** `TokenizeParam` 使用 `eval_tokenize` 的 `TempAllocGuard` 提供的分配器，省去每次调用独立创建和销毁 arena。外层 guard 覆盖参数求值、分词、JSON 打包的完整生命周期，嵌套 guard 会保留正在使用的临时内存；结果仍由既有 JSON 打包函数复制至表达式结果内存。

3. **IK 字符编码表寻址。** [IK 用户态采样](../benchmarks/fts-2026-round6/token_ik-profile.txt) 出现字典字符表查找与 DAT 转移开销。字符表容量改为至少原需求量的 2 的幂，查找、插入以位掩码替代除法取模；步长 3 与容量互质，能遍历全部槽位。Murmur 哈希、字符完整比较、字符到代码的映射与分词规则保持不变。这是内存中重建的字典结构，字符表容量可能接近原来的两倍，其他 DAT 数组没有扩容；这项内存代价不能忽略。采样按二进制内事件归一，包含后台线程，模板符号还可能经相同代码折叠，不能据平面符号名称推算精确收益。

## 正确性

11 套 mysqltest 全部通过：IK/BMW seek、score filter、build batch、batch merge、hotpath、TOKENIZE、simple query、parser properties、NULL ID merge，以及两类建索引测试。构建回归包含 MINOR FREEZE 后从 SSTable 建索引。

另通过 1,668 组完整结果差分、1,302 组扩展分词和排名分页差分、1,062 组 Unicode 差分，以及 8 连接各 200 次并发调用、异常恢复和长文档检查。每次切换二进制先后核对同一份索引，候选新建的索引也由旧二进制读取核对。验证实际 ID、相关性结果、分页、token 和词频，未以命中数量代替结果核对。

在既有 hotpath 套件补充重复配置、跨行更换解析器/配置、同一 SELECT 的多个不同配置、异常恢复，以及 15 字符词跨越 max_token_size=10/12/18 的用例。预期结果由旧二进制生成，再在候选上验证；见 [记录](../benchmarks/fts-2026-round6/max-length-regression.txt)。

## 分词内部诊断

通过 SQL BENCHMARK 连续执行表达式，减少逐请求客户端和唤醒开销。诊断输入取自原基准文本，追加由 RAND 生成的空格或标点，并显式转换为 UTF8MB4，避免常量折叠；这不是计分基准。每进程、每解析器测量 5 组，每组 20,000 次；顺序为旧、仅配置候选、最终候选、最终候选、仅配置候选、旧。所有组均保留，两个进程的全部 10 组取算术均值，两个版本均限制到 CPU 0–3。CPU 为进程 user+system 时间，包含后台开销，不等同于分词函数独占时间。

| 操作 | 旧版本 ms/次 | 最终候选 ms/次 | 耗时下降 | CPU 消耗下降 |
| --- | ---: | ---: | ---: | ---: |
| IK | 0.040956 | 0.037477 | 8.50% | 7.61% |
| BENG | 0.009701 | 0.006663 | 31.32% | 31.66% |

[全部内部采样及均值](../benchmarks/fts-2026-round6/isolated-summary.json) 和 [逐请求诊断](../benchmarks/fts-2026-round6/pilot.json) 均保留。仅配置候选的 IK 内部均值退化，不能用 BENG 的收益替代对 IK 的验证。最终候选加入字典寻址改动后，两项内部耗时及进程 CPU 均同向下降。

## 完整基准与不利结果

执行两组完整六轮基准，每组顺序均为旧、新、新、旧、旧、新，每个版本三轮取算术均值。每轮 SKIP_LOAD=0，重新导入 20,000 文档并构建索引；batch=500、rounds=3000、query_rounds=200、samples=3、warmup=30。每次启动后额外等待 15 秒再调用原脚本，等待发生在基准计时之外。

第一组使用原有 CPU 调度，整体退化；因此没有直接依据局部分词测试提交，而是补测相同资源条件下的固定 CPU 组。第二组把两个版本的全部服务器线程都限制在同一 CPU 0–3，其他配置相同。两组条件不同，分别报告，不混合均值，不删除退化项。
