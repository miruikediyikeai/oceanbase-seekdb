# 全文索引第四轮优化

本轮对照提交为 `8e5bca2c9cd138e8f2c6b629f427cd2cf675d50d`。该版本正式反馈的综合提升率为 16.1205%，原始性能分为 32.2409/100，折合约 16.12/50。正式 baseline 尚未提供，本轮只报告相对于该提交的本地增量，不预测正式分数。

## 定位依据及修改

在原始 20,000 行基准表上对 IK 索引重建、中文查询、英文查询和 IK 分词分别采样。构建样本仍出现字典范围查找、字符集比较及排序比较；查询样本出现逐行数组访问、相关性过滤、布尔表达式分派和 BM25 位图操作。本轮没有修改基准数据、SQL、计时、评分脚本或固定 baseline。

- 对索引范围已经确定、批次中不扩容的检索缓冲区，直接访问连续存储，减少每条 posting 上重复的数组访问包装。保留原有合并次序、权重乘法次序、去重、LIMIT/OFFSET 和错误处理。
- 仅对直接以 double 相关性列为参数的 `BOOL(score)`，使用与原表达式一致的 `score != 0.0` 判定，保留负零和 NaN 的比较语义。原相关性仍完整计算，先缓存每条有效结果的分数，再在批次输出时统一投影，减少每条候选记录上的临时投影与位图更新。过滤表达式的求值状态失效，其他消费者可从最终分数正常求值。阈值、组合表达式等继续通过原表达式引擎处理。
- BM25 批次没有跳过行、也没有已求值行时，保留逐行 NULL 检查和原算术公式，计算后统一设置有效前缀的完成位。稀疏或部分求值批次保留原实现。

字典范围二分定位、IK 私有链映射免锁及共享排序键直接访问也曾一起测试，但未获得足以支持整体提交的性能证据，已撤回。测试记录保存在 [撤回候选记录](../benchmarks/fts-2026-round4/rejected-combined/bench/comparison.json)。最终源码修改限定在检索与 BM25 五个文件，分词器和共享排序保持对照版本实现。

## 正确性与测量方法

新增 `fts_score_filter_regression` 的预期结果由对照二进制记录，覆盖分数投影、阈值与 BETWEEN 过滤、NOT/OR/布尔模式、空搜索、空结果、预编译语句重用，以及 255/257 附近的分页边界。IK 用例覆盖词典范围两端的词项、缺失字符、smart/max_word、日韩文字和解析器反复使用。

另外核对 1,668 组既有完整结果差分、1,062 组 Unicode 分词差分、8 个连接并发分词、落盘后索引构建及辅助表全部 posting 的统计校验、普通 SQL 全排序/TopN/窗口/聚合差分。完整性能测试使用原始默认参数，两个版本各三轮，交错执行并重新导入数据。单次计时与编译、正确性测试、采样分开。

## 首版候选的负面证据

首版候选尚未延后临时分数投影，其六轮记录全部保存在 [pilot](../benchmarks/fts-2026-round4/pilot/comparison.json)。构建类别平均退化 1.51%，分词退化 17.50%，查询下降 12.15%，三类等权综合退化 2.29%。虽然英文查询下降 26.22%，仍没有将该版本直接提交。

首版的额外 IK 重建采样耗时 21.70 s，对照为 9.53 s；前者 arena 复用的自身采样占比达到 36.71%，属于不利记录，不能忽略。该采样发生在长文本、Unicode、并发和排序回归之后，与完整基准的重启及重新导入流程不同，故不将单次采样耗时作为正式构建收益。它提示解析器保留内存的历史状态也会影响构建，需要继续关注。

首版整进程 CPU 诊断见 [原始记录](../benchmarks/fts-2026-round4/pilot/cpu-diagnostics.json)。整进程包含启动和后台任务，连 SELECT 1 也有显著差异，不能把全部差异归因于代码。后续尝试读取 SQL 请求线程 CPU ticks，但请求线程在测量中退出，故该次诊断作废。

## 撤回的混合候选

包含字典、仲裁器和共享排序修改的第二个候选，全部六轮记录保存在 [对照数据](../benchmarks/fts-2026-round4/rejected-combined/bench/comparison.json)。构建平均退化 1.14%，分词退化 34.42%，查询耗时下降 17.72%，三类等权综合退化 5.95%。这些记录全部保留，没有剔除分词较慢的轮次。

为减少后台线程影响，另以 perf 的 `cpu-clock`、999 Hz 采样并按 `ReqWorker` 汇总采样 period，执行顺序为旧、新、新、旧，每版本两次。它能够包含新建和退出的请求线程，采样没有丢样，结果哈希一致。[原始记录](../benchmarks/fts-2026-round4/rejected-combined/sampled-request-cpu.json) 显示四项查询的采样 CPU ms/次分别由 1.8371 / 2.5128 / 1.9124 / 2.7462 变为 1.1739 / 1.6224 / 1.4667 / 2.3581；IK 分词由 0.1488 变为 0.1225，但未修改实现的 BENG 分词由 0.0778 变为 0.0955。采样包含整个请求处理开销，且与完整基准使用不同客户端，仅用于定位，不能代替正式计时或计算成绩。

因此保留有查询计时及 CPU 证据的检索改动，撤回没有稳定整体收益的字典、仲裁及共享排序改动，并对缩小后的版本重新构建、验证及完整测量。

## 构建与核验

最终 `make -j3 seekdb` 完成 Release 编译和链接，二进制 SHA256 为 `277901ba2709994369b968ba8d5ac4ccdd4f975cafe4e6cc07e178ab479bd714`。Windows 提交目录与 Linux 编译目录的五个修改文件、四个已撤回修改文件逐字节一致，基准五个文件也逐字节一致。最终十套 mysqltest、1,668 组结果差分、1,062 组 Unicode 差分、并发解析和 20,000 行普通 SQL 排序/TopN/窗口/聚合差分全部通过。每次切换二进制前后都在同一份索引上核对结果，最终候选构建的索引也由对照二进制重新读取核对通过。重新建索引可能改变内部统计及分数，故不混用重建前的分数作为差分基准。

六轮查询命中数均为 8,001 / 11,000 / 7,332 / 20；命中数只是辅助检查。构建、执行、回归日志及源码哈希见 [核验记录](../benchmarks/fts-2026-round4/final/verification.json)。时间同步服务已恢复，未修改测试数据、SQL、计时逻辑、评分脚本、baseline 或 CI 工作流。
