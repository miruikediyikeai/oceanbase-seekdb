# 全文索引热路径优化与验证

## 范围与定位

本次优化基于 `063ab5ed9af3750b7551e0297439e68a162fdce8`，保留该提交已有的 AI 与 SQL 修复。没有修改 benchmark 的数据生成、SQL、计时、评分脚本或固定基线。

在专用本地实例上，使用完整的 20,000 篇文档基准采集用户态 CPU 栈（全系统 `perf record -a -e cpu-clock:u`）。23,435 个样本、无丢样；以下比例以采样期间全部用户态 CPU 为分母，包含并行构建及后续分词、查询，不能当作单条 SQL 的占比：

| 热点 | 采样占比约值 | 优化依据 |
| --- | ---: | --- |
| UTF8MB4 字符串 Datum 比较 | 4.5% | 排序中反复比较相同词项 |
| UTF8MB4 排序规则比较 | 2.3% | 重复词项无需重复计算排序权重 |
| 排序比较函数数组的虚拟 `at()` | 1.9% | 每次比较重复访问固定的排序元信息 |
| UTF8MB4 字符解码 | 1.9% | IK 的多个类型判定重复解码同一字符 |
| `ObSRDaaTIterImpl::filter_on_demand` | 0.6% | 无相关性过滤时仍逐行保存和恢复表达式上下文 |

## 内核修改

1. IK 字符分类只解码一次，仍按原先顺序判定英文字母、数字、中文、其他 CJK 和 UTF16 代理项；把已经取得的字符、长度和类型传给各个 processor。
2. whitespace 扫描对单字节 ASCII 直接前进一个字节；其他输入保留字符集解码器。BENG 的 ASCII 检查与小写缓冲区写入合并为一遍；`I` 和非 ASCII 仍走原字符集转换。
3. 全文词频聚合改为一次 hash 桶查找并原地更新，避免二次查找、替换节点的分配与释放。保留原实现首次计数为 1、后续累加 `word_freq` 以及最后一次排序规则等价词的拼写。
4. 排序初始化时缓存字段编号、比较函数和方向，热循环直接读取连续的元信息；任意键数、NULL、升降序、编码排序和比较范围仍沿用原有语义。保留取消检查和错误传播。
5. 字符集比较在完成原有参数校验后，对等长且字节完全相同的字符串直接返回相等；不同字节仍交给原排序规则，不能用字节顺序替代 CI/PAD SPACE 等规则。
6. DAAT 仅为 `VARCHAR + CS_TYPE_BINARY` 文档 ID 选择字节序比较函数；其他类型保持原比较函数。无相关性过滤的合并行直接返回，省去未被使用的表达式 batch 状态保存和恢复。

## 正确性验证

新增 mysqltest：`tools/deploy/mysql_test/test_suite/fts_index/t/fts_hotpath_regression.test`，结果文件由优化前的实例生成，不用新版输出覆盖预期。覆盖：

- IK smart/max_word、全角、中文量词、日文、韩文、emoji；BENG 标点、控制符、NUL、长重复文本、空文本、土耳其字母。
- `cafe/café`、`ecole/école` 等排序规则相等但字节不同的词，核对词频、文档长度和保留拼写。
- CI/BIN、尾空格、NULL、超过四个排序键、正反序、LIMIT/OFFSET、窗口分区、聚合及 JOIN。
- 加载后创建 IK/BENG 索引、完整命中文档 ID 和相关性分数、布尔检索、无命中、插入、更新、删除及回滚。

另保存优化前后完整结果作差分核对：固定随机种子的 Unicode/混合长文本、五种 parser、两种输出模式、字符集转换，以及基准数据上的完整文档 ID、相关性分数与过滤分页结果；共 1,668 组，其中 1,388 组成功，280 组为本构建不支持字符集的既有错误。普通 SQL 另用 20,000 行长字符串核对完整排序、Top-N、窗口及聚合结果。

查询差分必须在同一份索引上切换二进制进行：重建表后相关性统计可能略有变化，不能直接拿两次重建产生的分数作逐位比较。在同一索引上前后版本的 1,668 组输出完全一致，快照 SHA-256 为 `fb3ebedb7872bf65b93fd738bf0f99b4a0b630c1eef0946fd7053836395a6bf8`；普通 SQL 大数据排序快照 SHA-256 为 `1572c1ae4609e2d6f4ce7047748043d9a302892b4394faa7ca4371b80c9c18d4`。

## 性能复现

测试机：Intel Core i5-1240P，WSL2 Ubuntu 22.04，8 个逻辑 CPU、约 12 GiB 内存；同一编译目录，Clang 17，Release `-O2`。同一数据目录、启动参数与客户端，测试期间不运行编译或 perf。关闭本地自动校时后测量；一次出现负时长的旧报告已弃用。报告中的源码版本为 `unknown`，因为 Linux 编译目录是源码副本；版本通过保存的二进制和源码同步记录标识。

每次运行原版 `tools/benchmark/fts_large_bench.sh`，使用新报告文件，参数均为：`ROWS=20000 BATCH=500 ROUNDS=3000 QUERY_ROUNDS=200 SAMPLES=3 WARMUP=30 SKIP_LOAD=0`。三类等权，先平均类别内的单项耗时下降率，再平均三个类别；不能把九项直接平均。

本地前后对比及原始报告见下方验证记录。由于硬件、编译和运行环境与 CI 不同，本地相对下降率用于判断修改收益，正式成绩以统一评测为准。

## 验证记录（2026-11-01）

前后版本分别运行三次完整基准。每次基准内部仍为三组采样，下面是三份报告中各项指标的算术平均值，保留全部有效报告，不挑选最快一次。运行顺序为 before-1、before-2、after-1、after-2、before-3、after-3；重启后先执行相同的分词/查询快照以预热字典。原始报告及汇总 JSON 位于 [benchmarks/fts-2026](../benchmarks/fts-2026/)。

| 指标 | 优化前 | 优化后 | 耗时下降 |
| --- | ---: | ---: | ---: |
| `build_ik_all_sec` | 10.4427 s | 9.5870 s | 8.19% |
| `build_ik_content_sec` | 8.6317 s | 7.5190 s | 12.89% |
| `build_beng_en_sec` | 4.8890 s | 3.7563 s | 23.17% |
| `tokenize_ik_avg_ms` | 0.2155 ms | 0.2054 ms | 4.72% |
| `tokenize_beng_avg_ms` | 0.1595 ms | 0.1477 ms | 7.38% |
| `query_cn_avg_ms` | 2.5067 ms | 2.0002 ms | 20.21% |
| `query_beng_avg_ms` | 3.3047 ms | 3.1468 ms | 4.78% |
| `query_mixed_avg_ms` | 2.8297 ms | 2.4914 ms | 11.95% |
| `query_limit_avg_ms` | 2.7993 ms | 3.0166 ms | **-7.76%** |

类别平均下降率：构建 **14.75%**、分词 **6.05%**、查询 **7.29%**；三类等权综合下降 **9.36%**。本地结果未达到耗时减半，不能据此承诺统一评测满分。

LIMIT 项存在退化和运行波动，已保留其负提升率。另在同一份索引上切换二进制、以 `perf_counter` 对相同 SQL 作定向诊断（每版 3 × 500 次、不参与正式计分），LIMIT 均值为优化前 2.5303 ms、优化后 2.5841 ms；中文查询为 1.9195 ms、1.9031 ms。此诊断也不能证明 LIMIT 获得收益，因此没有用它替换原始基准数据。后续应在统一 CI 上重点复核 LIMIT 与短查询波动。

所有完整基准的查询命中数量均为 `8001 / 11000 / 7332 / 20`，同时完成上述完整结果差分。原固定 baseline 文件 SHA-256 为 `f4e97eddb2e49c982b967fc8047f7cf37177eebe53d648f6746d85aacda91f0c`。

Release 编译成功。以下七个 mysqltest 在新版通过：`fts_hotpath_regression`、`tokenize_function`、`simple_query`、`parser_properties`、`domain_id_merge_with_compare_null`、`create_table_with_fts_index`、`create_fts_index_afterward`。

环境限制：旧版 `basic_dml` 已在读取本地内部列元数据时失败（返回 `No such row` 后被当作 SQL 拼接）；`partitioned_simple_query` 因专用实例没有 `admin` 账号中止。未将这两项记为通过。TOKENIZE 的非 UTF8MB4 字符集支持和直接传入 LOB 的既有限制未在本次改动中扩展；长字符串回归显式转换为 CHAR。
